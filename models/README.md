The custom footprints declare native `cadModel` props. Existing vendor models remain in their component files; `index.ts` supplies the previously missing package models. The public OBJ models render in the viewer, and STEP links support CAD export. Package origins and rotations are declared in source.

The JTAG/reset/power headers, USB-A sockets and RGB LEDs use local declarative JSCAD meshes. Header contacts match the footprint positions and selected nominal body dimensions. The USB-A and LED bodies are visual package approximations, not mechanical acceptance models. Use manufacturer drawings for enclosure design. The two bare PCB test pads use native metal discs matching their footprint diameters, with a nominal 35 µm surface thickness; they do not represent fitted components. This also covers the built-in `smtpad_circle` footprints that the 3D converter currently omits. No generic bounding-box fallback is intended.

Vendor package geometry comes from the [JLCEDA](https://lceda.cn)/[EasyEDA official library](https://easyeda.com), served by `modelcdn.tscircuit.com`. Models remain referenced at their public URLs; they are not redistributed as local assets.

Run `bun --smol check-models.ts` after building. It verifies physical-part coverage, fetches every external OBJ/STEP with viewer CORS headers, validates asset formats, and checks that the official 3D converter produces a finite, non-empty mesh for every part. It also checks built-in footprint models. Board drills and textures are omitted only in this read-only validation; the generated board is never modified. To check another viewer origin, pass native-file path, report-file path, and origin as the three arguments.
